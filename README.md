# 盲僧 busy·blind

[![CI](https://github.com/KymeFran/Fuckthon/actions/workflows/ci.yml/badge.svg)](https://github.com/KymeFran/Fuckthon/actions/workflows/ci.yml)

> 给忙碌的人的闭眼修行：一款**闭着眼也能玩**的专注/呼吸训练 App。
> 声音即界面——所有玩法核心判定都走听觉，画面只是睁眼时的奖励层。
> 产品规则见 [`docs/盲僧·设计方案.md`](docs/盲僧·设计方案.md)，技术方案见 [`docs/忙僧·构建方案.md`](docs/忙僧·构建方案.md)，原始策划案在 [`docs/文件资料/`](docs/文件资料/)。
>
> 玩法规则已于 2026-09-07 对齐会议全部拍板并落地（8 项决策全部实现，见设计方案第九节）。

## 玩法总览（对齐后口径）

### 修 · 六个修行插件

| 修行 | 玩法 | 修为规则 |
|---|---|---|
| **木鱼** | 心里守住 1 秒一击的节奏，敲满 108 声；无节拍音，每 36 声极轻磬应答，节奏跑偏音色变闷 | 完成 = 15 − 偏移秒数（与满拍总时长 107s 的差，快慢都扣，下限 0） |
| **数雨** | 3 分钟白噪声里雨滴每 3–10 秒落一滴（无钟声），全程不动手只管默数；听完弹报数页对账 | 完成 = 10 − 数数误差（\|报数−实际\|，下限 0） |
| **听潮** | 潮涨按住吸气、潮落松开呼气（开始界面可选 4-6 / 盒式 / 4-7-8 呼吸法，憋气段保持按住）；相位吻合叠入风铃 | 分钟数 × 2 × 同步率 |
| **钓花** | 长按把浮标落在手指处（涟漪惊散花瓣，花瓣随后慢慢聚拢，拖动再惊散）；"叮"= 花瓣碰竿 1.5s 内收手，"咚"= 空竿；甩得越久机会越大（前 2 秒必空） | 钓到花瓣数 × 3 |
| **过河** | 听"叮——咚"在心里复现间隔 T∈[0.6,2.0]s 长按复现；窗口 max(15%T, 180ms)，1.5 倍内踩滑不死；每 5 跳扩大范围、第 10 跳起 叮-咚-咚 变奏 | 每跳 100 × (1−偏移率)，结算 = 总分/100 |

### 僧 · 主界面

- **修为条**：八级称号 浪子 → 居士 → 行者 → 沙弥 → 比丘 → 方丈 → 罗汉 → 菩萨（10000+）。
- **禅（打坐）**：常驻基础态，+1 修为/60s，单日上限 60；反挂机三重判定（退后台暂停 / 每 5 分钟磬声 30s 内在场确认 / 陀螺仪检测走动暂停）。
- **签（每日一签）**：**+10 修为** + 一张写在树叶上的签文，收入收藏。
- **成（成就 + 图鉴）**：成就列表 + 修为等级表 + **花瓣图鉴**——花瓣不分物种，攒够瓣数按档合成一朵花：
  - 4 瓣：桂花（常见）/ 丁香（稀有）
  - 5 瓣：桃花 / 梨花 / 樱花（常见）与 海棠（稀有）
  - 6 瓣：迎春（常见）与 水仙 / 百合（稀有）
  - 8 瓣：莲花（奇珍）
- **友**：好友修为与成就、交换花瓣——全 app 唯一联网功能，暂未接后端。
- **我 · 修炼报告（LLM，可选）**：把修行记录聚合成纯数字摘要，交给 OpenAI 兼容大模型（默认智谱 GLM `glm-4-flash`，可切换 DeepSeek / OpenAI / 全自定义），手动生成一份四段式禅意报告（本期概览 / 值得肯定 / 可精进处 / 下期建议），缓存本地最近 10 份。未配 Key 或断网时可一键生成本地模板版。**隐私：只上传聚合统计数字（次数、时长、修为、误差、同步率等），签文文本与逐次记录明细不出本机；API Key 明文存在本地 JSON。**

原则：**修为只来自真实专注**。能挂机、能后台偷跑的口子都视为 bug；宿主按 `meritBase×3` 统一封顶后单点入账。

## 快速开始

### 环境要求

- **Flutter SDK** ≥ 3.47（stable；开发机装在 `~/development/flutter`，建议把 `~/development/flutter/bin` 加进 `PATH`）
- **iOS**：Xcode（App Store 完整版）+ CocoaPods（`brew install cocoapods`）
- **Android**：Android Studio（自带模拟器与 SDK）
- 无需后端：数据全部本地优先，断网时除"加好友"外功能完整。修炼报告的 AI 生成是唯一可选联网项（自备 OpenAI 兼容 API Key，不配也能用本地模板版）

### 首次启动（三步）

```bash
git clone git@github.com:KymeFran/Fuckthon.git   # 或 HTTPS 地址
cd Fuckthon/busy_blind
flutter pub get
```

```bash
flutter run                        # 首次会编译原生工程，iOS 约 3–5 分钟
```

### 选择设备

```bash
flutter devices                    # 当前可用设备
open -a Simulator                  # 打开 iOS 模拟器再 flutter run
flutter emulators --launch <id>    # 启动安卓模拟器
flutter run --release              # release 模式（音视频时序更真实）
```

建议优先**真机 + 耳机**验证：这套玩法的命门是声音时序，模拟器音频延迟偏大，只能验证功能、不能验证手感。

### 不装任何环境，直接装到手机（Android）

每次推送后 CI 自动构建 release APK：仓库 **Actions → 最新一次运行 → Artifacts → `busy_blind-apk`** 下载安装（需允许"安装未知来源应用"）。iOS 因签名限制需 TestFlight 路线。

### 测试与工具

```bash
flutter test                       # 92 个测试（时钟调度 / 五个修行 / 视觉快照 / 本地存储 / LLM 报告 / widget 冒烟）
flutter analyze                    # 静态检查（当前零问题）
dart run tool/gen_sounds.dart      # 需 FFmpeg；合成 16 个 MP3 音效（正式音效直接替换 assets/sfx/ 同名文件）
```

### 常见问题

- `flutter: command not found`：Flutter 不在 PATH，`export PATH="$HOME/development/flutter/bin:$PATH"` 或用全路径调用。
- iOS 报 Pod 错误：`cd ios && pod install --repo-update`；换过 Flutter 版本先 `flutter clean`。
- 首次启动没声音：确认 `flutter pub get` 成功（音效在 `assets/sfx/` 随包加载）；仍无声则跑一次音效生成脚本再 `flutter clean && flutter run`。
- 想清空数据重新体验：「我」页签 → 清空本地数据（调试）。

技术栈：Flutter + audioplayers（短音效预载内存池）+ flutter_riverpod + 本地 JSON 存储（预留 Drift 迁移位）。

## 架构

```
lib/
  core/audio/        基座一：AudioClock 单一微秒时间源 / EventScheduler 按音频时间预排事件
                     （200ms 提前预约、暂停恢复节奏不乱）/ SoundBank / InputCapture / SessionRecorder
  core/practice/     基座二：修行插件契约（Manifest/Session/Result/Context）+ PracticeHostPage 统一结算收口
  core/llm/          OpenAI 兼容客户端（修炼报告；默认智谱 GLM，错误映射成一句话）
  domain/            修为等级 / 成就 / 花瓣与花 / 签文 / 修行统计摘要（报告上传的全部内容）
  data/              AppStore（本地优先 JSON 存储，字段即未来 Drift 表草图）
  shell/ features/   三页签「修/僧/我」+ 僧页四按钮页面 + 教程/校准/修行列表
  practices/         六个修行插件——新增修行 = 加一个文件 + 注册表一行，不动宿主
  widgets/           Low-Poly 按钮 / 修行场景（六张 WebP 氛围底图 + 原生动态前景）/ 曲线 / 花瓣图鉴组件
tool/gen_sounds.dart FFmpeg 音效合成脚本（分音轨采样率，资产已压缩至 0.45MB）
```

两条硬规则贯穿全部实现：

1. **时机即体验**：所有判定用音频时间戳（含 L_out 输出延迟与 L_user 用户校准补偿），不用墙钟。首次使用有 16 拍校准环节，把耳朵和手指的偏差写进 `L_user`。
2. **插件可插拔**：静坐一分钟只用注入的四件套实现，零改动宿主——这是模块化的验收标准（该修行现已移出列表，仅保留为教程试玩用例）。

## 实现口径（对齐会议后的剩余拟定项）

1. **AudioClock v0.1 用单调时钟**而非原生音频渲染时钟；接 AVAudioEngine/Oboe/soLoud 时只换实现。是否升级待真机试听验证。
2. **修为公式在会话内、clamp 在宿主**：公式属于玩法规则（新修行不改宿主），宿主统一封顶并单点入账。
3. **数雨报数页** 3 分钟无人确认自动收口且不发修为；未听完就退出同样不发。
4. **花瓣同档抽取权重**：常见 1.0 / 稀有 0.35（拟定值，待手感调优）。
5. **听潮修为公式**（分钟 × 2 × 同步率）未在对齐会议清单内，沿用原拟定值。
6. 手动结束的修行（听潮/钓花）右上角"结束"入口为临时交互，待设计确认。
7. 好友（Supabase）未实现，占位已留；打坐陀螺仪反挂机已上线（sensors_plus，无传感器平台静默降级）。
