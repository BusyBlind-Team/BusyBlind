# 盲僧 busy·blind · 设计方案

> 给协作伙伴的设计总览：讲清"做什么、规则是什么、为什么这么定"，**不涉及具体技术实现**。
> 技术方案见《忙僧·构建方案》，对外简介见《忙僧·概念介绍》。

---

## 一、产品与命名

**一句话**：给忙碌的人的闭眼修行——一款集成式互动冥想 app，面向时间碎片化的上班族。每次修行几分钟，闭眼、听声、做一个小互动，缓解视疲劳、放空思维、提升专注。

**名字**：「盲僧」与「忙僧」同音。闭眼修行的人是"盲僧"（blind），偷出五分钟的人是"忙僧"（busy）——所以叫 busy·blind。

---

## 二、五条设计原则（所有讨论的前提）

1. **闭眼可玩。**
   任何玩法都必须在"熄屏 / 闭眼"的前提下完整成立；屏幕上的画面是睁眼时的奖励，不是必需品。

2. **时机即体验。**
   所有与节拍、间隔、时机相关的声音和判定必须精准、无延迟。凡是因卡顿导致的节奏错乱，一律按 bug 对待——节奏一抖，用户的呼吸就乱了。

3. **修行是可插拔的模块。**
   新增一个修行 = 一份玩法规则 + 一组音效 + 列表里的一个条目，不改动其他任何部分。
   验收标准：用它做一个"静坐一分钟"的最简修行，如果需要动公共部分，模块化设计就不合格。

4. **数据本地优先。**
   断网时除"加好友"外，全部功能可用；服务器只负责同步与好友社交。

5. **修为只来自真实专注。**
   任何能挂机、能后台偷跑的口子都视为 bug。好友排行里的每个数字都必须是真的。
   与框架提示词"每日抽签 +10 修为"的冲突已于对齐会议解决：抽签维持原设的 +10 修为（见第九节 #4），修行的修为仍只来自真实完成。

**打坐不在修行列表里**——它是主界面的常驻基础态，没有列表入口、没有结算页，退出即回主界面。

- 进入后锁屏式全屏，仅保留低亮度的盲僧立绘（OLED 省电）
- 每满 60 秒有效时长 +1 修为，**单日上限 60 点**（上限为本方案新增）
- **反挂机三重判定**（本方案新增）：
  1. app 进入后台立即暂停计时；
  2. 每 5 分钟一声极轻的磬，30 秒内轻触任意处确认在场（不确认则暂停计时，不惩罚）；
  3. 陀螺仪检测到持续大幅位移（如走路）暂停计时。
- 退出：长按盲僧立绘 2 秒（"长按解除"为原设，2 秒阈值为防误触拟定）

## 六、五个修行的详细规则

### 1. 木鱼（专注 · 节奏保持）

- **108 下**，目标间隔 1000ms。策划案为 300 下/300 秒，已拍板定 108（佛家百八之数、单局约 2 分钟更贴碎片时间）。磬声节点（36 的倍数）与结算均基于 108。
- **无外部节拍音**——节拍必须来自用户内心，否则这不是专注训练而是跟拍游戏。
- 过程反馈仅两处：
  - 每 36 下（三分之一）一声极轻的磬；
  - 偏差累积超过阈值时，木鱼音色微微变闷——只暗示，不打断。
- 结算：总时长与满拍总时长（107 秒，108 声之间只有 107 个间隔）的差值 → 心急（快）/ 走神（慢）判定；输出间隔序列曲线；稳定性指标（间隔标准差）。
- 修为（已拍板）：完成一次 = **15 − 偏移时长（秒）**，四舍五入、下限 0；偏移 = 总用时偏离满拍总时长的绝对值（快了叫心急，慢了叫走神，同样扣）。未完成一次不发修为。
- 眼态：全程闭眼。

### 2. 数雨（专注 · 听觉计数 + 白噪声）

- 时长 **3 分钟**，背景为鸟鸣虫鸣白噪声（约 -24dB）。
- **雨滴**：每 3–10 秒落下一滴（区间内均匀随机），期望约 28 滴。
- **没有钟声**（已拍板删去）。
- **计数方式**（已拍板）：过程中**不实时计数**，全程不用动手，只管在心里默数；3 分钟后雨停，弹出报数页询问"你听见了多少滴雨"，报数与实际对账。报数页若 3 分钟无人确认，自动收口且不发修为。
- 结算：报告"你报 N，实际 M"，误差 ≤10% 为优秀。
- 修为（已拍板）：完成一次 = **10 − 数数误差**（误差 = |报数 − 实际| 的绝对滴数），下限 0；未听完就退出不发修为。
- 眼态：全程闭眼（报数页睁眼）。

### 3. 听潮（呼吸 · 助眠）

- 潮汐节奏引导呼吸：默认 4 秒吸 / 6 秒呼（涨潮音渐强 4 秒，落潮音渐弱 6 秒）。
- **互动已拍板保留**：吸气时长按屏幕，呼气时松开，结算计算呼吸与潮汐相位的同步率。
- 反馈：按压与潮汐相位吻合时，潮声中叠入一层极轻的风铃；偏离时无惩罚、无声音。
- 三档节奏：入门 4-6、标准 4-7、深度 4-8（后者接近助眠的生理触发区）。
- 结算：呼吸同步率曲线（复用木鱼的曲线组件）+ 平均同步率。
- **助眠模式**：勾选后结束不弹结算页，音频渐弱至静音、屏幕保持黑屏，修为次日打开时补发。
- 眼态：全程闭眼。

### 4. 钓花（耐心 · 收集）

> 策划案原机制：长按甩杆垂钓；"叮"= 花瓣碰竿，松手钓起；"咚"= 不是花瓣，钓不起；花瓣缓慢漂动；甩杆越久花瓣靠近概率越高；刚甩杆会击散附近花瓣。花瓣永久保存，按投入瓣数合成一朵花，入图鉴。

- **玩法循环**：长按甩杆 → "聚瓣期"（触竿概率随本次甩杆时长上升，拟：10 秒约 20% → 60 秒约 60%）→ 触竿响"叮"（花瓣，拟 65%）或"咚"（杂物，拟 35%）→ "叮"后 1.5 秒内松手收杆；"咚"后松手为空竿 → 松手后 2 秒休竿期，进入下一轮。
- **耐心训练的两个抓手**（策划案机制的直接转译）：
  - 刚甩杆的前 2 秒概率为 0 且击散附近花瓣——急躁直接受损；
  - 甩得越久机会越大——但"咚"杂物也随之变多，逼你在"再等等"和"该收手"之间做听觉判断。
- **听觉化改造（已确认成立）**：策划案中花瓣漂动、击散都是纯视觉信息，与"闭眼可玩"原则冲突。改造后核心判定全部走听觉（叮/咚），花瓣漂动的画面降级为睁眼奖励层——闭眼时它照样在跑，只是不依赖它做判定。
- **浮标视觉（已拍板）**：长按后在手指处投下浮标，播放"略微放大 + 点起涟漪"的入场动画；附近花瓣按距离远近不同程度散开，之后慢慢、带随机扰动地向浮标靠近；按住拖动（移动浮标）也会使花瓣散开。花瓣聚散只是氛围层，不参与叮/咚判定。
- **反挂机**：连续 90 秒无有效输入自动进入结算；挂机不放杆钓不到任何东西。
- 结算：本局有效时长、钓起花瓣数、"咚"误收次数、"叮"未接住次数、平均等待时长；花瓣入库动画在结算页（睁眼奖励）。
- 修为（已拍板）：**钓到花瓣数 × 3**（钓到的花瓣是真实所得，与结束方式无关）。
- **收集线**（已拍板）：花瓣不分物种，按投入瓣数分档合成一朵花——4 瓣：桂花（常见）/ 丁香（稀有）；5 瓣：桃花 / 梨花 / 樱花（常见）与海棠（稀有）；6 瓣：迎春（常见）与水仙 / 百合（稀有）；8 瓣：莲花（奇珍）。同档内按稀有度抽取。图鉴在"成"页常驻入口；好友可交换花瓣（走"友"按钮）。
- 眼态：开局睁眼看规则 → 全程闭眼。

### 5. 过河（专注 · 节奏复现）

- 每一跳：先播"叮——咚"，两者间隔 T 随机取 0.6–2.0 秒；用户长按屏幕，在自认为 T 之后松开。
- **起手口径**：按下时刻不作硬判定（以"咚"响起的时刻为计时锚点，起手早晚只计入曲线）；硬判定只有"松手时刻 − 咚时刻 ≈ T"。体感与策划案一致：听到叮预备，咚响起时按下。
- 判定窗口：`max(T × 15%, 180ms)`。
- 三段判定：窗口内 = 成功；窗口 1.5 倍内 = 踩滑（不死，但难度不递进）；超出 = 失败结束。
- 难度递进：每 5 跳，T 的取值范围扩大，并引入"变奏"（叮-咚-咚，需复现第二段间隔）。
- 结算：最高连续跳数写入成就；修为（已拍板）= **总分 / 100**（四舍五入、下限 0），每跳得分 = 100 × (1 − 偏移率)，偏移率 = |松手偏差| / 本段间隔 T。
- 眼态：开局睁眼看规则 → 全程闭眼；结算页展示走过的石阶。

## 七、教程与声音语言

教程的本质是教一门**声音语言**，建议首启三段式：

1. **声音语义表**（全 app 统一）：

   | 声音 | 语义 |
   |---|---|
   | 磬一声 | 开始 / 请闭眼 |
   | 磬两声 | 结束 / 可以睁眼 |
   | 极轻的磬 | 打坐在场确认（30 秒内轻触任意处） |
   | 叮 —— 咚 | 过河：间隔度量（复现它） |
   | 叮 / 咚 | 钓花：花瓣 / 杂物（叮则收手） |
   | 木鱼声 | 节拍锚（用户自己敲出） |

   ⚠️ 叮/咚在过河与钓花中**语义不同**（间隔度量 vs 物件判定），音效需用不同音色或包络区分，教程分别教学，否则用户会迁移错误预期。

2. **60 秒试玩**：用"静坐一分钟"最简修行当试玩——它同时是模块化设计的验收用例。

3. **校准环节**：跟着节拍轻点 16 次，取偏差中位数。此后所有时机判定都会贴着用户的耳朵来算，用户无感知。

修为规则的说明放教程尾页，并在"成"页常驻入口。

> 数值口径补充（实现时拟定的细节，后续可再调）：
> - 木鱼"偏移时长"= 总用时与满拍总时长（107 秒，108 声之间只有 107 个间隔）差值的绝对值；未完成一次不发修为。

> - 花瓣同档抽取权重：常见 1.0 / 稀有 0.35；钓花所得花瓣与旧档"按物种存储的花瓣"迁移为总瓣数。
