## 发布签名

发布 APK 必须使用团队保管的固定密钥。后续更新继续使用同一应用 ID 和签名，并递增 Android versionCode。

密钥及密码不得提交到仓库。CI 发布时由维护者设置的 Secrets 提供；PR 验证工作流不读取发布密钥。普通 CI 测试包和正式签名包应清楚区分。

首次从内部调试包迁移到正式签名包时，可能无法直接覆盖安装。先确认记录保留方式，再在 Release 中说明；不要把卸载当作无损升级步骤。

参考：[Android 应用签名](https://developer.android.com/studio/publish/app-signing)。

## 开源前

1. 保留代码 MIT 许可证及已有第三方声明；素材来源和署名按[素材核对表](ASSET_LICENSE_REVIEW.md) 后续补充，保留[素材反馈入口](../ASSET_NOTICE.md)。
2. 检查当前文件及 Git 历史中的密钥、个人数据、内部地址和不宜公开的材料；`docs/文件资料/` 中的原始文档也在公开范围内。发现真实凭据时先撤销或轮换，再处理历史。
3. 确认 README 中的功能、下载入口和平台范围与待发布版本一致。

仅从 README 移走历史说明不会让原文件或 Git 历史变成私有。

## 产出与验证

1. 将发布所需 PR 合并到 `main`，固定待发布 commit SHA。
2. 更新 `pubspec.yaml` 中版本与 build number，静态分析、测试及 APK 构建通过。
3. 从同一提交产出正式签名 APK，验证签名、版本、包名与资源打包结果。
4. 在 Android 真机验证冷启动、五个练习、退出结算、后台恢复和升级安装。
5. 对最终 APK 计算 SHA-256，记录签名证书 SHA-256 指纹。
6. 使用新的 tag 创建 GitHub Release 草稿，附 APK、校验文件和发布说明。
7. 最后确认公开范围，再将仓库公开并发布 Release。

发布说明草稿见 [RELEASE_NOTES.md](RELEASE_NOTES.md)。
